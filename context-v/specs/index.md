* [Corpora Builder Harmony — the evolving test registry](Corpora-Builder-Harmony-Test-Registry.md) - Every proposed and implemented test guarding the corpora builder and the systems it must harmonize with — identity, workspace connector, transport, state, canonical layer, files — in human language, MECE, one ✓-phrase each.
* [Strategy Curator — An Entry-Point App for augment-it](Corpora-Curator-Entry-Point-for-Augment-It.md) - A canonical source registry in SurrealDB owns identity, the client's filesystem owns usage, and a shared UUID is the only bond.
* [Corpus Inbox — capture first, triage later; a zero-friction save destination for URLs without a home yet, with a future triage layer that sorts inbox content into the right places](Corpus-Inbox-Capture-and-Triage.md) - A URL with no home yet shouldn't cost a filing decision: `corpus/inbox/` captures the page, its body, and a drive-by note, then waits.
* [Design System Convergence — the organ registry, its five verdicts, and the fingerprint ledger that catches drift while it happens](Design-System-Convergence.md) - The registry is what makes drift legible: a declared organ is a decision, an undeclared one is drift. * [Design System Portal](Design-System-Portal.md) - Specification for the portal that renders the federated design system — the swatch page, the token catalogue, the member index.
* [Enhanced Records List — the Triage Checkpoint and the Promotion Loop](Enhanced-Records-List-and-Promotion-Checkpoint.md) - One record-grained view of a whole enrichment round: select the good rows, promote them to canonical, and the predecessors archive.
* [Entity-Card Edit & Remove Affordances — every visible property gets a micro-button pair](Entity-Card-Edit-And-Remove-Affordances.md) - The org card views and edits in place, but only additively — a misclicked ➕ today required a direct database write to undo. Every entry and identity property the card shows grows ✎ and × micro-buttons.
* [Entity-Pulse Bundle — Press Releases, News Mentions, and the Social Voice of a Record](Entity-Pulse-Bundle.md) - Official Updates fires first; its rollup becomes the relevance prior for Media and Socials Mentions — a foundation-first four-phase DAG.
* [Federated Component Libraries](Federated-Component-Libraries.md) - One gallery runtime, seventeen sovereign catalogs — every member publishes what it is made of, at its own address.

* [Flow for Bundles & Packs — The Simplest Possible Thing](Flow-for-Bundles-Packs.md) - For 67 rows with a website URL, find each one's blog index. Two surfaces, no reviewers — this spec deliberately ignores the five before it.
* [Funder Content Corpus Workflow — what the system has to do, ranked by quality bar, with no implementation prescribed](Funder-Content-Corpus-Workflow.md) - Written so a future agent resists the pull to filter yesterday's bad data tighter instead of firing fresh for today's good data.
* [Initial User Experience — From Landing to a Productive First Action](Initial-User-Experience.md) - What the first thirty seconds of augment-it feel like: a productive first action without a lecture, skippable and never re-shown.
* [Per-Record Iteration as the Primary Surface for Pack and Bundle Fires — The Flow Rearranges Per Fire Type](Per-Record-Iteration-as-Primary-Surface-for-Pack-Fires.md) - A pack fired across 96 rows returned 0 found — so per-record iteration becomes primary and bulk fan-out waits until a chain is proven.
* [Pulse Curation Layer & UI — Three Layers per Category, Triage Per Item, Finalize on Demand](Pulse-Curation-Layer-and-UI.md) - Three layers per category: immutable `raw_output`, live `curated_output`, and a `finalized_output` snapshot locked when triage is done.
* [Pulse pattern — one operator burst against one entity, expressed as N independent pulse-dimensions composed in a pulse-surface, each dimension potentially owning its own microservice](Pulse-Pattern.md) - Operators enrich in bursts, not steps: one search fills name, socials, emails, and org, and a pulse-surface commits all of it in one save.
* [Record ↔ DB Resolver — operator-driven match/create bridge from row-store records to canonical organizations](Record-DB-Resolver.md) - Row-store records and canonical SurrealDB orgs were never bridged; the resolver closes the gap one record at a time, operator driving.
* [Record-Set Family Grouping — internal lineage vs. external-variant families in the Record Collector sidebar](Record-Set-Family-Grouping.md) - The sidebar shows a tracker uploaded as v4–v8 as five unrelated CSVs. Two family kinds — promotion lineage and external variant — fix that.
* [Records Surface sort step and UI — sort ships as part of the **Sort & Filter Lens**, the second lens in step 2's default set (alongside the existing **Pack Firing Lens**); `lens` is the architectural primitive this spec introduces and lenses are *swappable* (one active per step at a time), not stackable; each step ships with a small curated default lens set and the registry stays *open* so new lenses can join without architecture changes](Records-Surface-Sort-Step-and-UI.md) - Sort ships as the second swappable lens on step 2 — and the lens registry is open, so a new lens is a manifest drop, not an enum edit.
* [Request Reviewer — the Pre-Flight Surface](Request-Reviewer-Pre-Flight-Surface.md) - See exactly what is about to leave the building — and guarantee the request you reviewed is byte-identical to the one that fires.
* [Response Reviewer Shell and Content-Reader Mode — Response Reviewer becomes a wrapper whose inner review UI swaps based on what the bundle that fired actually produced](Response-Reviewer-Shell-and-Content-Reader-Mode.md) - 1,109 OfficialPulse responses, 3 accepts: 'is this URL right?' is the wrong question for content packs, so review mode becomes swappable.
* [Response Reviewer and Response Store — the Post-Flight Surface](Response-Reviewer-and-Response-Store.md) - No review surface until a fired response is a first-class stored object — so response-store and response-reviewer are specced as one.
* [Search-Results Queue — a right-rail microfrontend where concurrent agent searches land, signal, and get triaged](Search-Results-Queue-Remote.md) - Agent searches run minutes; the operator shouldn't. Every search becomes a card in a persistent right rail — fire many, triage on arrival.

* [Shell & Micro-Frontend UX Coherence — Affordances That Are Found, Consistent, and Talk Back](Shell-and-Micro-Frontend-UX-Coherence.md) - A demo-prep chain of 'I can't find / reach / trigger X' is a verdict: the shell's affordances hide, die, or mismatch. Fix the pattern.
